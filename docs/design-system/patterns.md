# 画面と文言のパターン

## 入力と保存

- 単一の入力はFieldでラベル・説明・エラーを関連付ける。
- 動的な入力にも一意のidと名前を付ける。複数入力のまとまりにはfieldsetとlegendを使う。
- 保存待機はButtonのloadingとフォームの無効化で示す。
- 保存失敗後は入力値を保持し、再実行できる状態に戻す。
- 一部だけ保存できた場合は、保存済みの内容と次の操作を明示する。[画像付き保存](../../apps/cafelog/src/lib/saveLog.ts)が実装例である。

## データ取得と空の一覧

- 取得中はLoading、失敗時はErrorStateと再試行、データがない場合はEmptyStateを使う。
- エラーを空データと同じ表示にしない。
- 絞り込みで0件になった場合は、元のデータがない場合と文言を分ける。
- 読み込みや取得失敗のテスト用応答は[画面検証](../../scripts/ui/baseline.mjs)に追加する。

## 通知と確認

- 操作が完了したら結果を通知する。失敗の通知には、次にできる操作を書く。
- Base UIの通知は、未展開時の読み上げ用領域と、フォーカス時の操作を分けて提供する。
- モーダルは名前を持たせ、背景の操作制限、Tab移動、Escape、閉じた後のフォーカスを確認する。
- ページ内の削除確認では、確認見出しへフォーカスを移し、キャンセル後に元のボタンへ戻す。[記録詳細](../../apps/cafelog/src/pages/LogDetail.tsx)が実装例である。

## 固定ナビと画面の余白

- AppShellとPageLayoutで本文の幅と下余白を決める。ページ側で同じ余白を重ねない。
- 固定ナビの高さ、セーフエリア、本文末尾の余白を揃える。
- 末尾の入力・保存・フォーカスがナビに隠れないことを実際に操作して確認する。
- 現在のナビ項目はaria-currentで示す。装飾だけで選択状態を伝えない。

## 日本語の文言

- 操作は「保存する」「削除する」「再試行」のように動詞で書く。
- ラベルで項目を説明し、placeholderだけに頼らない。
- 失敗の文言は、何ができなかったかと次の操作を短く書く。
- 長い店舗名・豆名・URL・メモを折り返す。重要な値を省略する場合は、全文を確認する手段を用意する。
- 同じ操作や状態には同じ言葉を使う。新しい文言は両アプリの利用箇所も確認する。
