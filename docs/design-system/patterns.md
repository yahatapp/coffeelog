# 入力と保存のパターン

実装中のガイド。対象画面の移行状況と確認結果は[実施記録](migration-status.md)を参照する。

## 入力を関連付ける

単一の入力にはFieldを使い、id・ラベル・説明・エラーを結ぶ。既存のフォーム管理は維持し、Fieldが渡す属性をInput・Select・Textareaへ適用する。動的な入力は、行と用途から一意のidを作る。

複数の操作をまとめる場合はグループの名前を付ける。注ぎ方のように行の中に複数の選択欄がある場合も、各欄の用途が分かるラベルを付ける。表示位置や色だけで区別しない。

## 保存中と保存失敗

保存処理中はButtonのloadingを使う。入力条件を満たさず操作できない状態とは分けて扱う。全幅の保存ボタンにはfullWidthを使い、背景色や高さを呼び出し側のCSSで上書きしない。

保存に失敗した場合は入力を残し、再試行できるようにする。成功後の遷移と一覧・詳細の再取得は既存の更新処理で行い、結果を共通の通知で伝える。取得に失敗した画面にはErrorStateと再試行を用意する。

## 固定ナビとの配置

本文はAppShellとPageLayoutで配置する。ページ側で固定ナビ用の下余白を重ねて指定しない。ナビの高さとセーフエリアを共通管理し、末尾の入力や保存操作が隠れないことを確認する。
