# デザインシステムの変更記録

## 2026年11月3日：器具管理と両アプリの画面を整理

- Brewlogのドリッパー・グラインダー管理を標準カードに揃え、フォームの見出しや入力欄全体に付いていた不要な枠線を取り除いた。挽き目の設定をfieldsetでまとめ、狭い画面では入力欄を縦に並べる。
- 共通Checkboxの表示を小さくし、44px以上の操作領域を維持した。両テーマの部品一覧に、操作領域の端でのクリック、Spaceキー、フォーカス、無効状態の検証を追加した。
- Brewlogの豆一覧の編集と店舗一覧の戻る操作を共通Buttonに揃えた。両アプリの設定カードの余白と見出しを整え、Cafelogの記録詳細ではフレーバーノートを縦に配置した。
- 確認対象は、両アプリのホーム、一覧、詳細、登録・編集、店舗、設定と、Brewlogの器具管理。通常・長文・空・取得失敗・保存失敗の状態を、既存の画面検証と器具名の長文ケースで確認する。

## 2026年11月1日：SelectとInputの高さ

- WebKitでSelectの最小高さが反映されず、Cafelogの精製方法と焙煎度に高さの差が出ていた。共通Selectに入力用トークンの高さを明示し、両アプリでInputと揃えた。
- 両テーマの部品一覧とCafelogの新規・編集フォームに高さの検証を追加した。画面検証はWebKitも選べるようにした。実行方法は[表示・操作の検証](accessibility.md)を参照。

## 2026年11月1日：ヘッダーなしのカードの余白

- CardContentがカードの先頭にある場合にも上の余白を確保し、Cafelog設定のプロフィールとアプリ情報の表示を修正した。
- CardHeaderがあるカードの余白は維持した。両テーマの部品一覧とCafelog設定の画面検証に余白の確認を追加した。

## 2026年11月1日：標準CSSへの一括移行

- トークンの値をCSS、公開名・型・必須条件をcontract、利用方法をこのガイドへ分けた。
- 両テーマの補助文字、薄い面、入力境界、操作・通知・温度・焙煎度の役割を整備した。
- 共通UI、両アプリの全画面、Field、固定ナビ、Dialogと画像操作をCSS Modulesへ移した。
- Tailwindと関連依存、旧変数、仮のCSS公開口を削除した。
- 両テーマの部品一覧、トークン・CSS・クラス参照・ガイドの検査、画面・操作・アクセシビリティ検証を整備した。
- 両アプリの公開と公開後の確認を完了した。[公開結果と復旧手順](release-verification.md)を参照。
- 変更理由と確認結果は[実施記録](migration-status.md)、最終確認と公開は[実装計画](../design-system-implementation-plan.md)に記録する。
